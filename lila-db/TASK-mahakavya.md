# Задание: лилы «Чайтанья-чаритамрита-махакавьи» Кави Карнапуры → база лил

Для отдельного чата, где уже сделан (и сверяется) перевод Махакавьи. Цель — внести в `lila-db/` все лилы
Махакавьи (20 сарг) по тем же правилам, что и для уже обработанных источников, со ссылками на стихи нашего перевода.
Лучше вести базу **после сверки каждой сарги** (или параллельно, но тогда при правке нумерации поправить `verses`).

## 1. Сначала прочитать
- `CLAUDE.md` (правила проекта: сохранность, богословие, только PD-тексты).
- `lila-db/README.md` (формат записей и событий — обязателен), `THEMES.md`, `PERIODS.md`, `SOURCES.md`, `PERSONS.md`,
  `PLACES.md`, `PLAN.md`.
- Образцы записей: `lila-db/lilas/murari-kcc.yaml` (Махакавья во многом следует Мурари — это главный ориентир для
  сопоставления), `lila-db/lilas/chaitanya-chandrodaya.yaml` (другое произведение Карнапуры).
- `sources/SURVEY-primary-sources.md`, строка 1.2 (о Махакавье и её изданиях).

## 2. Откуда брать
- Наш перевод Махакавьи (RU/EN) в этом чате — это и есть основной текст для базы. Файлы перевода должны лежать в
  репозитории **в той же ветке**, что и `lila-db/` (иначе `build.py` не найдёт стихи): если перевод в другой ветке
  или папке — сначала слить/перенести его в `claude/book-translation-tesseract-bengali-yaygag` (например,
  `karnapura-mahakavya/ru/NN.md`, `en/NN.md`, метки стихов `**N.**` — как в других переводах; одна сарга — один файл).
- Санскритский оригинал — для сомнительных мест; ЧЧ/ЧБ — только для полей `cc`/`cb` (не уверен — не заполнять).
- Сверка последовательности лил — с нашими переводами Мурари (`murari-gupta/ru/`; Карнапура во многом следует
  Мурари) и «Чайтанья-чандродаи» (`chaitanya-chandrodaya/ru/`).

## 3. Что делать
1. В `SOURCES.md` добавить строку:
   `| karnapura-ckm | Кави Карнапура, «Шри-Чайтанья-чаритамрита-махакавья», 1542 | `karnapura-mahakavya/` | A | Санскр. поэма в 20 саргах; во многом следует Мурари |`
   (папку указать фактическую).
2. Создать `lila-db/lilas/karnapura-ckm.yaml`: записи `kcm-0001`, `kcm-0002`… **в порядке изложения**, одна запись —
   один эпизод. Поля — по README:
   - `ref: "Сарга 4, 12–40"`, `file` — файл RU-перевода сарги;
   - `verses` — **обязательно**: `{file: "karnapura-mahakavya/ru/04.md", from: "12", to: "40"}` по меткам `**N.**`
     (лила через границу сарг — несколько отрезков); `build.py` проверит, что стихи есть, и построит ссылки RU/EN;
   - `summary` — 1–2 фразы своими словами;
   - `event` — обязательно. **Сначала искать существующее событие** (`python3 lila-db/query.py text:…`,
     `grep -i … lila-db/events.yaml`, `EVENTS.md`) — большинство лил уже есть (Мурари, Лочан, Джаянанда, драма,
     пады). Новое событие — только если лилы действительно нет, по правилам именования README;
   - `parallels` (особенно «Мурари N.N.N», где Карнапура следует Мурари), `divergence` (где расходится с Мурари/ЧЧ/ЧБ);
   - `themes`/`bhava`/`teaching`/`scriptures`/`calendar`/`years`/`date_basis` — как в других источниках; даты,
     прямо названные в поэме, особенно ценны (`date_conf: точно`, `date_basis: "Махакавья 3.12"`);
   - `authority: A` по умолчанию; понижать (явный поэтический вымысел, небесные сцены) — только с пояснением в `notes`;
   - вступления, мангала, колофоны — `kind: author`, без события.
3. Новые теги лиц/мест — сначала в `PERSONS.md` / `PLACES.md` (проверить, нет ли уже этого лица под другим тегом).
4. Богословие (в `summary`/`notes`): глазами гаудия-вайшнава (авторитет — Бхактисиддханта); никаких майявадских или
   мирских формулировок (Господь не подвластен майе, Божество — не «статуя», према гопи — не мирская страсть, о
   Господе не «смерть» — «сокрытие»). Где Карнапура расходится с богословием или с ЧЧ — коротко в `notes`/`divergence`.
5. Проверка после каждой порции: `python3 lila-db/build.py -w` — **0 ошибок, 0 предупреждений**;
   `python3 lila-db/query.py source:karnapura-ckm -l` — выборочно посмотреть.
6. В `lila-db/PLAN.md` — строку о статусе Махакавьи (сколько сарг внесено).

## 4. Порядок и сохранность
- Порциями по 2–3 сарги; после каждой — `build.py`, коммит и пуш (правило `CLAUDE.md`: ничего не оставлять
  несохранённым). Исполнителей-субагентов — по одному, последовательно.
- **Параллельная работа:** в другом чате идёт перевод пад, который тоже пишет в `lila-db/` (`lilas/padas.yaml`,
  `events.yaml`, `PERSONS.md`). Чтобы не было конфликтов:
  - свои записи — только в `lilas/karnapura-ckm.yaml`;
  - в `events.yaml`, `PERSONS.md`, `PLACES.md`, `SOURCES.md` — только **дописывать в конец** (новые события —
    в конец файла; порядок на шкале задаётся полем `order`, не местом в файле); существующие события не
    переписывать, разве что дополнить пустые `cc`/`cb`/`date_basis`, если уверен;
  - перед каждым коммитом: `git pull --rebase --autostash origin <ветка>`; при конфликте в сгенерированных
    файлах (`TIMELINE.md`, `EVENTS.md`, `export/*`) — взять любую сторону и заново запустить `python3 lila-db/build.py -w`.
- Ветка: `claude/book-translation-tesseract-bengali-yaygag` (если чату назначена другая — работать в ней, а при
  слиянии сгенерированные файлы пересобрать).

## 5. Итог
Отчёт пользователю: сколько записей, сколько новых событий, какие лилы известны только Махакавье, главные
расхождения с Мурари и ЧЧ, найденные даты.
