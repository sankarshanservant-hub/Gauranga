# База лил Шри Чайтаньи (сводная)

Все лилы Махапрабху, описанные в переводимых писаниях, — на условной временной шкале Его жизни. Для каждой лилы:
в каком писании и где она описана, кто из спутников участвует (единые именные теги), где это происходило,
насколько авторитетен источник. Тексты переводов эту базу не содержат — она ведётся отдельно.

## Файлы
- `lilas/<источник>.yaml` — записи по одному источнику, **в порядке изложения в нём** (например, `lochana-cm.yaml`).
- `PERIODS.md` — периоды временной шкалы (коды `P00`…`P15`) с примерными датами.
- `SOURCES.md` — коды источников и их авторитетность (A/B/C/D).
- `PERSONS.md` — реестр именных тегов `@…` (единый формат, одно лицо — один тег).
- `PLACES.md` — реестр тегов мест `#…`.
- `THEMES.md` — реестры меток: темы (`themes`), бхава/облик Господа (`bhava`), темы учения (`teaching`).
- `events.yaml` — сводные лилы-события (одно событие ← записи разных источников); `events-*.yaml` — события,
  заведённые параллельной работой (напр. `events-karnapura.yaml`), читаются вместе с основным.
- `build.py` — проверяет всё и собирает `TIMELINE.md` (для чтения) и `export/*.json` (технический слой для сайта,
  приложения, поиска: `lilas.json` — записи с подставленными годами/возрастом и засвидетельствованностью,
  `events.json`, `meta.json` — все реестры). Сгенерированное не править вручную.
- `query.py` — поиск из командной строки (теги, темы, годы, возраст, текст; см. начало файла).

## Формат записи
```yaml
- id: lcm-0001                 # <код источника>-<порядковый номер>, не меняется
  source: lochana-cm           # код из SOURCES.md
  ref: "Сутра-кханда, «Грантхарамбха», 15–40"   # где в источнике (часть, раздел, стихи; как в нашем переводе)
  file: "lochana/ru/02.md"     # файл нашего перевода (если есть)
  period: P00                  # код периода из PERIODS.md
  order: 10                    # порядок внутри периода (по традиционной хронологии; 0–1000, приблизительно)
  date: ""                     # дата/возраст, если источник или традиция её указывает («1486, пхалгуна-пурнима»)
  title: "Нарада в Двараке"    # краткое название лилы (RU)
  summary: "Кришна открывает Нараде, что явится как Гаура..."   # 1–2 фразы (RU), без оценок
  persons: ["@krishna", "@narada", "@rukmini"]   # все участники-тег из PERSONS.md
  places: ["#dvaraka"]                            # теги из PLACES.md
  kind: pre-advent             # lila | pre-advent | prophecy | vision | teaching | miracle | post-advent | author
  authority: B                 # по умолчанию — как у источника; понизить для явных вставок/спорных мест
  parallels: ""                # где ещё описано (если известно): «Мурари 1.02–1.03; ЧБ Ади 2»
  notes: ""                    # богословские оговорки, пояснения
  # --- поля для поиска (необязательные; пустые можно не писать) ---
  themes: [revelation, kirtan]  # 1–4 кода тем из THEMES.md, главные первыми
  bhava: [radha]               # облик/бхава Господа в лиле (THEMES.md), если существенно
  teaching: [holy-name]        # темы учения (THEMES.md) — для наставлений
  scriptures: ["Бхаг. 11.5.32"]  # цитируемые/толкуемые места шастр, как в тексте сносок
  calendar: ""                 # месяц/титхи/праздник, если назван: «пхалгуна, пурнима»; «ашадха, 7-й день, воскресенье»
  years: [1509, 1510]          # годы н. э. (диапазон); не указано → из события, иначе из периода (PERIODS.md)
  age: [23, 24]                # возраст Господа; не указано → вычисляется из years (от 1486)
  date_conf: оценка            # точно | вероятно | оценка
  date_basis: ""               # на чём основана дата: «Мурари 2.1: в 22 года»; «по Ч.-ч. Мадхья 1»
  cc: ""                       # соответствие в «Чайтанья-чаритамрите»: «Ади 17» (глава; стихи — только если уверены)
  cb: ""                       # соответствие в «Чайтанья-бхагавате»: «Мадхья 13»
  divergence: ""               # кратко, чем рассказ расходится с другими источниками
  event: ev-jagai-madhai       # id сводного события (events.yaml) — ОБЯЗАТЕЛЬНО для всех записей, кроме kind: author
  verses:                      # ОБЯЗАТЕЛЬНО: с какого по какой стих описано, по меткам **N.** в файле нашего перевода (ru)
    - {file: "lochana/ru/30.md", from: "49", to: "126"}
    - {file: "lochana/ru/31.md", from: "127", to: "169"}   # лила через границу файлов — несколько отрезков
    # метки — как напечатаны: "80", "371a", "80+3", "94+24"; если метка в файле повторяется (новый раздел начал
    # нумерацию заново) — "2:25" = второе вхождение «25». Для Мурари: {file: "murari-gupta/ru/2.13.md", from: "1", to: "27"}
    # Тексты без нумерации (драма «Чайтанья-чандродая», проза): отрезок по фрагментам строк (точная подстрока,
    # уникальная в файле; to_text ищется после from_text):
    # - {file: "chaitanya-chandrodaya/ru/03.md", from_text: "**Шачи.** Сын мой", to_text: "Все уходят"}
```
`build.py` проверяет, что стихи существуют, и строит ссылки (RU и EN) с номерами строк: в `TIMELINE.md`, `EVENTS.md`
и `export/lilas.json` (поле `verses_resolved`: file, from, to, line, line_to, count, url, url_en).
Правила: одна запись — одна лила (эпизод). Если источник лишь упоминает событие вскользь — запись с `kind`
по смыслу и пометкой «упоминание» в `notes`. Новые теги сначала добавить в `PERSONS.md` / `PLACES.md`.

## События (`events.yaml`) — единое пространство лил
Каждая лила получает одно каноническое имя, общее для всех писаний: событие `ev-…` с названием `title` (RU) и
`title_en`. Записи источников — это «описания» события; на сайте событие показывается со всеми описаниями и ссылками
на стихи (`EVENTS.md` — то же для чтения).
Именование: `id` — `ev-` + латиница через дефис по традиционному названию лилы, без привязки к источнику и без
номеров (`ev-jagai-madhai`, `ev-ratha-yatra-first`, `ev-sarvabhauma-deliverance`); `title` — краткое традиционное
название («Освобождение Джагая и Мадхая»). Гранулярность — эпизод: если один источник объединяет два эпизода, его
запись ссылается на главный, а второй указывается в `notes` (или запись делится на две). Лилы, известные лишь
одному источнику, тоже получают событие. Не создавать дубликатов: сначала искать (`python3 query.py text:…`,
`grep -i … events.yaml`).
Одно событие жизни Господа — одна карточка; записи разных источников ссылаются на неё полем `event`. На уровне
события уточняются датировка (`years`, `age`, `date_conf`, `date_basis`, `calendar`), `cc`, `cb`; записи без своих
значений наследуют их. Засвидетельствованность (`attestation` в export) = число разных источников события.
```yaml
- id: ev-jagai-madhai          # ev- + латиница через дефис
  title: "Освобождение Джагая и Мадхая"
  title_en: "Deliverance of Jagai and Madhai"
  period: P07
  order: 400                   # шагами 10 (можно дробные — 405.5), чтобы вставлять события других источников
  years: [1509, 1509]
  date_conf: вероятно
  date_basis: "…"
  cc: "Ади 17"
  cb: "Мадхья 13"
  themes: [mercy, offense]
  notes: ""
```
