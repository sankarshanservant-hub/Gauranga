чтение** главы `ed/vcd/CC_<Глава>.md`, за которое делается всё ниже. Прочитать один раз: `CLAUDE.md`, `TASK-full-edition.md`

## 1. Правки текста ВЧД → дописать в `ed/fixes/<Глава>.txt`
Формат строки: `@N поле: было => стало  # причина` (`tr` — перевод, `ww` — пословный, `tl` — транслитерация;
N — номер стиха или группы «65-66», как в метке «(65–66)»). `было` — точная подстрока.
- Только орфография, грамматика (падежи, пропущенные слова), пунктуация; **стиль переводчика не переписывать**.
- Пунктуация — грамматически правильная: тире «Кришна — это Владыка»; «О Господь!» (без запятой после «О»); запятые
  при вводных словах и оборотах; закрытые кавычки.
- Ссылки на шастры правит скрипт автоматически — не трогать.
- Пословный: опечатки; падеж по смыслу строки.
- **Недостающий пословный** (`python3 tools/check_ed.py <Глава>` → «нет пословного») — дописать в манере ВЧД:
  `@N addww: <начало строки транслитерации> => <пословный, слова через два пробела>  # нет пословного у ВЧД`
  и строку в `ed/review/missing.md`.
- Затем `python3 tools/prep_vcd.py <Глава> && python3 tools/check_ed.py <Глава>` — 0 ошибок, 0 «не применена».

## 2. База лил (за то же чтение)
- `lila-db/lilas/cc.yaml` (создать при первой главе): записи по порядку изложения, `id: cc-0001…`, `source: cc`,
  `ref: "Ади 1.1–17"`, `file: "chaitanya-charitamrita/ed/vcd/CC_<Глава>.md"`, `verses: [{file: …, from: "1", to: "17"}]`
  (метки — номера стихов «(N)»), все поля по `lila-db/README.md` (persons `@…`, places `#…`, themes/bhava/teaching по
  `THEMES.md`, years/age, date_basis, kind, authority A, event).
- События: сначала `python3 tools/cc_events.py <Лила-рус> <N>` (кандидаты по главе); иначе `python3 ../lila-db/query.py text:…`;
  новые события — в `lila-db/events-cc.yaml`. Главы-«таттвы» (вступления, учение) дают в основном `kind: teaching`;
  одна запись — один эпизод или одна цельная тема учения, не по стиху.
- `python3 lila-db/build.py -w` — 0 ошибок в своих записях; перед коммитом
  `git checkout -- lila-db/TIMELINE.md lila-db/EVENTS.md lila-db/export`.

## 3. Сохранение
После каждых ~30 стихов — правки и записи лил в файлы и сразу (одной командой) коммит и пуш. Объём на исполнителя — до
~250–300 стихов (2–3 небольшие главы). При обрыве — продолжить с последнего стиха в `ed/fixes/<Глава>.txt` / `cc.yaml`.
Коммит только своих файлов (`git commit -- <файлы>`), затем `git pull -q --rebase origin <ветка> && git push -q origin <ветка>`
(без --autostash). Отчёт — 5–10 строк.
