# Инструкция координатора: «Шри Чайтанья-чаритамрита», полное издание RU + EN

Этот файл — всё, что нужно новой сессии Claude (в любом аккаунте), чтобы продолжить работу с того же места и в том
же качестве. Читать целиком при старте. Всё остальное — в репозитории; вне репозитория только скан
(`src/CC_SS.pdf`, скачивается `setup.sh`) и временная рабочая папка (`/tmp/cc-work`, создаётся заново).

---

## 0. Роли и общий порядок

- **Пользователь** решает спорное (богословские и редакторские развилки, порядок работ). Пишет по-русски; отвечать
  по-русски, коротко, без технических подробностей. Каждую главу (или пакет коротких глав) пользователь начинает
  явно («Давай дальше», «Да»); после главы — короткий итог и вопрос «Продолжать?».
- **Координатор** (основная сессия) не переводит сам. Он готовит материалы скриптами, собирает задания исполнителям
  из шаблонов `prompts/`, принимает отчёты, проверяет спорные правки сам по бенгальскому, сливает части, собирает PDF,
  ведёт `PLAN.md`, сохраняет (коммит + пуш) после каждого шага.
- **Исполнители** (субагенты, инструмент Agent, в фоне): сверка бенгальского и проверка — Sonnet; этап А и перевод
  комментариев — Opus. Каждый читает правила сам (`TASK-*.md`, `STYLE-commentary.md`, глоссарии), пишет только свои
  файлы, коммитит порциями.

## 2. Перенос в новый аккаунт (один раз)

1. **Доступ к репозиторию.** Новый аккаунт Claude должен видеть GitHub-репозиторий `sankarshanservant-hub/gauranga`
   (подключить GitHub в claude.ai → Settings → Connectors, установить Claude GitHub App на репозиторий, или
   сделать форк/коллаборатора). Работать в той же ветке, где лежит последний результат (сейчас —
   `claude/focused-sagan-sbiwnn`), либо создать новую ветку от неё.
2. **Окружение Claude Code (облако):** сеть должна пускать `vedabase.io`, `archive.org`, `drive.google.com`
   (+ `drive.usercontent.google.com`), `pypi.org`, Ubuntu-зеркала apt. Если политика сети ограничена — разрешить
   эти хосты (или «полный доступ»). Нужен Chromium (в облачной среде Claude Code он предустановлен в
   `/opt/pw-browsers`; иначе — `CHROME=/путь/к/chrome`).
3. **Первое сообщение** в новой сессии — текст из `START.md` (копировать как есть).
4. Модели исполнителей: Opus и Sonnet (если в аккаунте нет одной из них — Opus для всего; Haiku не использовать).

## 2а. Локальный режим (VS Code / Claude Code на своём компьютере, без GitHub)

Используется автономный комплект (`KIT-README.md`): папка `cc-kit/` с проектом `gauranga/` и рядом `cc-work/`
(заранее подготовленные данные). Отличия от облачного режима:
- **Рабочая папка** `$W` = `cc-kit/cc-work` (скрипты находят её сами; `$CC_WORK` задавать не нужно). В ней уже есть:
  `scan1/tNNN.tsv`, `scan1/oNNN.txt` — OCR всех страниц скана Мадхьи (`tesseract` для них не нужен; картинки
  страниц `pNNN.pgm` отрисуются при подготовке главы — нужен poppler или PyMuPDF), `bsst/<Гл>.txt` — второй OCR
  (CCBSST); тексты vedabase уже в `ed/work/vb-<Гл>.json`. Поэтому `prep_chapter.sh` сеть не использует.
- **Сохранение:** `save.sh` и `commit_own.sh` делают локальный коммит; пуш — только если подключён удалённый
  репозиторий. В шаблонах заданий исполнители сохраняются через `bash tools/coord/commit_own.sh "…" <файлы>`.
- **Атрибуция коммитов:** строки из системного напоминания сессии — в `cc-work/trailer.txt` (один раз за сессию);
  скрипты и `prompt.py` берут их оттуда.
- **Карта страниц Мадхьи** и замеченные заранее сбои нумерации ВЧД — `MADHYA-NOTES.md` (не нужно запускать
  `locate.sh` на всю лилу; для уточнения границ главы он работает по готовому OCR мгновенно).
- **Резервная копия:** пользователь сам периодически копирует `cc-kit/`; напоминать ему после каждых 2–3 глав.
- Пути в заданиях исполнителям (`{{CC}}`, `{{W}}`) подставляет `prompt.py` — абсолютные пути этого компьютера.

## 3. Старт каждой сессии

```bash
cd <репозиторий>/chaitanya-charitamrita
bash tools/coord/setup.sh            # tesseract+ben, poppler, pip-пакеты, скачать CC_SS.pdf (72 МБ), найти Chromium
export COMMIT_TRAILER="<строки атрибуции из системного напоминания сессии>"   # для prompt.py/save.sh
sed -n '/Откуда продолжать/,/^### Расход/p' PLAN.md   # где остановились
git log --oneline -5; git status -sb
```
Прочитать один раз: этот файл, низ `TASK-full-edition.md` (решения), `WORKFLOW.md` § 7, `PLAN.md` (таблица).
Исполнительские `TASK-*.md` координатору читать не обязательно — их читают исполнители.

**Сохранность (требование пользователя, всегда):** после каждого шага и каждого отчёта исполнителя —
`bash tools/coord/save.sh "сообщение"` (коммит всего в `chaitanya-charitamrita` и `lila-db` + пуш с повтором).
Сгенерированные файлы `lila-db/TIMELINE.md`, `EVENTS.md`, `export/` не коммитить (save.sh их откатывает). Скан и
картинки страниц в репозиторий не класть. Если стоп-хук просит закоммитить — закоммитить и запушить.

## 4. Конвейер главы

### 4.1. Найти страницы и подготовить (координатор, скрипты)
```bash
bash tools/coord/locate.sh 276 320          # OCR диапазона: номера ॥N॥ и колофоны по страницам
bash tools/coord/prep_chapter.sh Adi17 276 310
```
Глава начинается на странице, где кончилась предыдущая (там «ইতি অনুভাষ্যে …», затем «কথাসার»), и кончается
страницей с «ইতি অনুভাষ্যে <N-й> পরিচ্ছেদ». `prep_chapter.sh` печатает всё, что нужно проверить глазами:
- **число стихов**: ВЧД (`prep_vcd`: «стихи 1–N»), vedabase (`extract.py`: страниц + группы `a-b`), скан (последний ॥N॥);
- **скачки нумерации ВЧД** («54→56», «110→164»): последний «১৬৪» — опечатка колофона, скрипт сам перенумерует;
  повтор номера (46, 46) — тоже сам; пропуск номера — смотреть исходник (`vcd/txt`): номер латинскими цифрами
  («॥ 55 ॥») → `@raw` в `ed/fixes/<Гл>-raw.txt` (Ади 16.55);
- **ошибки `check_ed.py`** («нумерация: перед ॥56॥ ожидался 55») — исправить до запуска исполнителей.
Расхождение ВЧД ↔ vedabase ↔ скан в числе стихов — разобрать (§ 6) до запуска этапа А (сверка бенгальского
может идти сразу: она и выясняет, каких стихов нет в издании).

### 4.2. Исполнители: что, когда, параллельно
| Шаг | Шаблон | Модель | Начинать | Объём на исполнителя |
|---|---|---|---|---|
| Сверка бенгальского со сканом | `prompts/sheets.md` | Sonnet | сразу после 4.1 | 1–3 главы |
| Перевод комментариев RU+EN | `prompts/commentary.md` / `commentary-part.md` | Opus | сразу после 4.1 | ≤ 15–20 стр. скана |
| Этап А (ВЧД: опечатки, пословный, EN-стихи, база лил) | `prompts/stageA.md` | Opus | после сверки бенгальского | ≤ 250–300 стихов |
| Выборочная проверка комментариев | `prompts/check.md` | Sonnet | после слияния комментариев | 1–3 главы |

Короткие главы — пакетом (2–3 главы одному исполнителю; Ади 8–9, 11–12, 13–15). Длинная глава (> 20 стр.) —
два исполнителя комментариев параллельно, деление **по номеру стиха** (не по странице): найти страницу, где
кончается раздел к стиху K (`grep -o '^[০-৯]\+।' $W/comm/<Гл>/pNN.txt`), часть 1 = стихи ≤ K, часть 2 = ≥ K+1,
стыковую страницу читают оба (Ади 10: 186–202 / 202–216; Ади 7: ≤92 / ≥93). Часть 2 пишет `*.p2.md`.

Сборка задания:
```bash
python3 tools/coord/prompt.py prompts/sheets.md CH=Adi17 PAGES="276–310 (…)" EXTRA="…" > $W/p-sheets.txt
python3 tools/coord/prompt.py prompts/commentary.md CH=Adi17 TOPIC="…" PAGES="276–310" BOUNDS="На с. 276 сначала конец Ади 16 (до «ইতি অনুভাষ্যে ষোড়শ পরিচ্ছেদ») — не переводить. …" EXTRA=""
python3 tools/coord/prompt.py prompts/commentary-part.md CH=Adi17 PART=2 RANGE="все разделы к стихам 170–334 и колофоны" SPLIT="≤ 169 — часть 1, ≥ 170 — часть 2" JOINT="293" PAGES="293–310" TOPIC="…" BOUNDS="…" OUTPUT="отдельные файлы \`ed/ru/Adi17-apb.p2.md\`, \`ed/ru/Adi17-anu.p2.md\`, \`ed/en/Adi17-apb.p2.md\`, \`ed/en/Adi17-anu.p2.md\` — без строки \`# …\`, сразу разделы \`## N\`." EXTRA=""
python3 tools/coord/prompt.py prompts/stageA.md CH_LIST="Adi17" CH=Adi17 TOPIC="…" LILA_ID=cc-0240 EXTRA="- …"
python3 tools/coord/prompt.py prompts/check.md CH_LIST="Adi17" CH=Adi17 PAGES="276–310" EXTRA="- сноски …; стык с. 293 …"
```
Длинный или содержащий обратные кавычки `EXTRA` передавать из файла: `cat > $W/extra.txt <<'EOF' … EOF`, затем
`EXTRA="$(cat $W/extra.txt)"` (иначе bash выполнит `…` как команду). Текст задания — целиком в `prompt` инструмента Agent (`run_in_background: true`, `model: sonnet|opus`,
`subagent_type: general-purpose`). Для части 1 длинной главы — `commentary-part.md` с `PART=1` и
`OUTPUT="\`ed/ru/<Гл>-apb.md\`, … (с заголовком \`# …\`)"`. Последний id базы лил: `grep -o 'id: cc-0[0-9]*' ../lila-db/lilas/cc.yaml | tail -1` (+1).

**EXTRA — самое ценное, что добавляет координатор:** всё, что он узнал при подготовке и из прошлых отчётов:
особенности нумерации, стихи с правками-словами (из отчёта сверки) — для этапа А; сноски и неясные места
переводчиков — для проверки; тема главы и трудные места (поэтика, астрология, родословные) — для переводчика.

### 4.3. Приём отчётов (координатор)
- **Сверка бенгальского** → список правок, меняющих слово/смысл, передать в `EXTRA` этапа А; отсутствующие/лишние
  стихи — решить по § 6 до этапа А.
- **Комментарии** → `python3 tools/coord/merge_parts.py <Гл>` (если были части; затем `git rm` файлов `*.p2.md`);
  глоссарии: `python3 tools/coord/merge_glossary.py "Ади 17" ed/work/glossary-Adi17*.md` и `git rm` их;
  вопросы переводчиков: сноски «В переводе стиха — иначе» ставить, где комментатор понимает стих иначе, чем ВЧД.
- **Этап А** → **сам проверить по бенгальскому каждый стих, исправленный «по смыслу»** (вывести бенгальский
  и новый перевод: скрипт-однострочник по `ed/vcd/CC_<Гл>.md`); исполнитель бывает слишком смел. Сомнительные
  места из отчёта — решить: бесспорное исправить (`ed/fixes/<Гл>.txt`), спорное — спросить пользователя
  (AskUserQuestion: варианты + рекомендация). Уход спутников: «умер/умерший» у ВЧД → нейтрально (Ади 15.24).
- **Проверка** → бесспорное проверяющий правит сам; «на решение» — решить координатору (смотреть бенгальский
  в `ed/bn/<Гл>-ocr.md` и изображение) или спросить пользователя. Если в выборке найдено существенное —
  проверяющий расширяет; если много — полная проверка главы.
После каждого отчёта — `save.sh`.

### 4.4. Завершение главы
```bash
bash tools/coord/finish.sh Adi16 [Adi17]   # prep/check/EN/PDF ×4 + размещение комментариев + lila-db build
```
Всё должно быть: 0 ошибок `check_ed`, «переведено N из N», «размещение: OK», «0 ошибок» lila-db. Затем:
- `PLAN.md`: строка главы в таблице статуса (образец — строки Ади 10–15) и «Откуда продолжать» → следующая глава;
- `save.sh "CC Adi 16 complete: …"`;
- отправить пользователю `ed/pdf/CC_<Гл>-full.pdf` и `CC_<Гл>-full-en.pdf` (SendUserFile);
- отчёт пользователю (по-русски, 6–10 пунктов): стихи (правки по скану, что исправлено в ВЧД по смыслу — примеры),
  комментарии (число разделов, сноски), проверка (что нашла), база лил (диапазон id, события, лица), сомнительные
  места, расход токенов (сумма `subagent_tokens` из уведомлений), следующая глава — «Продолжать?».

## 5. Качество: на чём уже обжигались (обязательно держать в голове)
1. **Аваграха ঽ печатается в издании как «হ»** — переводчики теряли отрицания (Ану 7.74: смысл наоборот). Отсюда
   п. 3а проверки: весь санскрит и все сноски «в издании ошибка» — по изображению, в каждой главе.
2. **Флаги OCR неполны** — сверка бенгальского читает все стихи по скану (с Ади 13).
3. **Старые бенгальские дроби:** «১॥০» = 1½, «১।০» = 1¼ (OCR их путает), «২।৩» = 2–3, «৪।৫ ক্রোশ» = 4–5.
4. **Стык частей:** раздел на границе терялся (Ади 5, Ану 48) — делить по номеру стиха, стыковую страницу читают
   оба; `merge_parts.py` + проверка «номера N। в OCR ↔ ## N».
5. **Номер стиха у ВЧД** бывает повторён, пропущен, латинскими цифрами, «১৬৪» в колофоне — смотреть вывод
   `prep_chapter.sh`.
6. **Атрибуции** не снимать по догадке (Ади 1.14/7.6: «дневник Рупы Госвами» оказался подтверждён подзаголовком
   «Анубхашьи»). Сомнение → сноска или вопрос пользователю, не правка.
7. **Чужие смыслы:** стоп-список «Нельзя» (`ed/GLOSSARY-commentary.md`): Божество — не «статуя/идол», йогамайя — не
   «иллюзия», према — не «страсть», уход — «уход», Купидон → Мадана и т. п. Богословски комментарий не оценивать.
8. **Цитаты ЧЧ в комментариях** из ещё не обработанных глав — из `vcd/txt` (только опечатки); когда дойдём до тех
   глав, расхождения ВЧД с изданием (напр. Антья 13.126 «собрание Рупы Госани», Мадхья 10.43 «махасояра») — сноски.
9. **BBT/Прабхупада** не открывать при переводе (только для понимания сомнительного места, своими словами;
   сравнение с Прабхупадой — отдельная задача, `WORKFLOW.md` § 4).
10. **Исполнители в параллели** коммитят только свои файлы, без `--autostash`; если `git pull` отказывает из-за
    чужих незакоммиченных файлов — просто `push`. Блокировка `index.lock` — подождать 2–5 с и повторить.

## 6. Особые случаи (рецепты)
| Случай | Что делать |
|---|---|
| Стих есть у vedabase, нет ни в ГМ, ни у ВЧД | `@vb skip: N  # …` в `ed/fixes/<Гл>.txt` (сдвиг сверки с vedabase) |
