# Проверка перевода комментариев главы (проход 3 по WORKFLOW.md) — постоянное задание

Проверяющий — не тот, кто переводил. Прочитать один раз: `TASK-commentary.md` (правила перевода), `ed/GLOSSARY-commentary.md`,
`GLOSSARY-vcd.md` § 5–6.

## Вход
- Перевод: `ed/ru/<Глава>-apb.md`, `ed/ru/<Глава>-anu.md`.
- Бенгальский: черновой OCR `ed/bn/<Глава>-ocr.md` (по страницам и колонкам); где OCR неразборчив или есть сомнение —
  изображение колонки `<scratch>/comm/<Глава>/pNN-{L,R}{1,2}.png` (смотреть только нужные).
- Перевод стихов ВЧД: `ed/vcd/CC_<Глава>.md`.

## Что проверять (по разделам `## N`, абзац к абзацу)
1. **Полнота и точность:** нет пропусков (фразы, цитаты, глоссы, перечисления), нет добавлений; верны числа, имена,
   номера стихов, ссылки на шастры; нет ли разделов, пропущенных целиком (сверить номера абзацев «N।» в OCR со списком `## N`).
2. **Термины:** по `GLOSSARY-commentary.md` и `GLOSSARY-vcd.md`; стоп-список «Нельзя» (Божество — не «статуя», йогамайя —
   не «иллюзия», према — не «страсть», уход — «сокрытие»). Содержание комментария богословски не оценивать.
3. **Цитаты ЧЧ** — дословно по переводу ВЧД из `ed/vcd/`.
4. **Стиль:** хорошая русская проза, не калька; ясность; опечатки, пунктуация.

## Выход
- `ed/review/check-<Глава>.md`: таблица «раздел | было | стало | причина» (только существенное) + итог: оценка полноты
  (% разделов без замечаний), типичные ошибки.
- Бесспорные исправления (пропуск, опечатка, ошибка в числе/имени, термин) — внести прямо в `ed/ru/…`. Спорное (смысл,
  толкование) — только в таблицу с пометкой «на решение».
- Коммит только своих файлов (`git commit -- <файлы>`), `git pull -q --rebase origin <ветка> && git push -q origin <ветка>`
  (без --autostash). Отчёт — 5–10 строк.
