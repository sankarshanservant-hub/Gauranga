# Рабочий перевод книги B («Шри Гаура-паршада о Гаудия-ачарьяганера чаритавали») силами GPT

Для проекта «Спутники Шри Чайтаньи» (`parshadas/`, ветка `claude/gracious-shannon-knppn0`). Книга B — бенгальская,
1194 с., ~150 жизнеописаний (сост. Шамбхунатх Дас Адхикари, Майяпур, Шри Чайтанья Матх, 2019). Чтение бенгальского
OCR и картинок страниц — самая дорогая часть работы Claude (пилот: до 39 млн токенов на одно лицо). Поэтому:

- **GPT** делает **полный, буквальный рабочий перевод B на английский** — постранично, с номерами страниц;
- **Claude** читает уже этот перевод (вместо бенгальского) при составлении реестров фактов и статей (`parshadas/TASK.md`)
  и выборочно сверяет его с оригиналом.

Перевод — **служебный**, для извлечения фактов. Книга под авторским правом (2019): перевод **не публикуется**, не
кладётся в публичный репозиторий и не используется как текст наших статей (статьи пишутся своими словами по реестру).

---

## 1. Почему на английский (а не на русский)
- GPT заметно точнее переводит с бенгали на английский, чем на русский.
- Для Claude английский текст в ~1,5–2 раза дешевле русского по токенам (кириллица дороже), а читать его придётся
  многократно.
- Реестр фактов и статьи всё равно пишутся заново по-русски и по-английски; литературный русский перевод книги
  проекту не нужен.
(Если пользователь захочет читать перевод сам — можно второй проход EN→RU, но это отдельная задача.)

## 3. Чем пользоваться (расширения и инструменты)
Есть два рабочих способа; первый — основной.

**А. OpenAI Codex (облачный агент, работает прямо в репозитории GitHub).**
1. В ChatGPT открыть Codex и подключить GitHub-аккаунт; дать доступ к приватному репозиторию `gauranga-private`.
2. Создать окружение для репозитория; в настройках окружения разрешить доступ в интернет (archive.org) и в
   скрипт установки (setup script) добавить:
   `apt-get update && apt-get install -y poppler-utils tesseract-ocr tesseract-ocr-ben`
   (poppler — `pdftotext`/`pdftoppm`; tesseract-ben — запасное распознавание).
3. Положить в репозиторий этот файл как `charitavali-en/TASK.md` и скрипт подготовки (§ 4).
4. Давать задания партиями: «Переведи главы 001–003 по `charitavali-en/TASK.md`», агент сам коммитит/делает PR.
(Названия и настройки продуктов OpenAI меняются — сверяться с их текущей справкой; суть: агент с доступом к
репозиторию, интернету и возможности ставить пакеты.)

**Б. ChatGPT (обычный чат) + Google Drive.**
1. В ChatGPT подключить Google Drive (Connectors / «Подключённые приложения») — тогда модель может открыть PDF с
   Диска. Либо загружать в чат сами страницы: PDF-фрагменты по 5–10 страниц или картинки страниц.
2. В «Проект» (Projects) ChatGPT загрузить этот файл как инструкцию проекта, чтобы он действовал во всех чатах.
3. Результат каждой главы сохранять в `.md` (кнопка копирования / скачивание файла) и загружать в приватный
   репозиторий через веб-интерфейс GitHub («Add file → Upload files») в `charitavali-en/`.
Способ Б проще в начале, но много ручной работы; при 150 главах лучше перейти на А.

**Модель:** самая сильная доступная модель GPT с чтением изображений (бенгальский часто приходится читать с картинки
страницы). Режим «рассуждения»/thinking — включать для трудных страниц (стихи, родословия, даты).

## 4. Подготовка страниц (один раз, способ А)
```sh
mkdir -p work && cd work
curl -sSL -o B.pdf "https://archive.org/download/EHso_shri-gaura-parshad-o-gaudiya-acharyaganera-charitavali-bengali-mayapura-shri-chaitanya-matha/Shri%20Gaura%20Parshad%20O%20Gaudiya%20Acharyaganera%20Charitavali%20Bengali%20-%20%20Mayapura%20Shri%20Chaitanya%20Matha_text.pdf"
n=$(pdfinfo B.pdf | awk '/^Pages:/{print $2}'); mkdir -p txt png
for i in $(seq 1 $n); do pdftotext -f $i -l $i B.pdf txt/p$(printf %04d $i).txt; done
# картинку страницы делать по мере надобности:
# pdftoppm -f N -l N -r 200 -png B.pdf png/pNNNN
```
Текстовый слой archive.org для бенгальского **ненадёжен** (перепутанные лигатуры, пропуски). Поэтому вся книга
заново распознана tesseract (ben, 300 dpi): **`ocr/B/pNNNN.txt`** в приватном репозитории `gauranga-private`
(NNNN — страница PDF) —
чистый текст в правильном порядке строк. Правило: **читать страницу по `ocr/B` и обязательно по картинке страницы** (каждую страницу
целиком): оба OCR — и tesseract, и archive.org — иногда **теряют целые строки** (пример: B 47, pdf 67 — пропали две
строки; в пилотном переводе одна из них оказалась пересказана с потерей фактов). Сверять число строк и ход фраз с
картинкой; строки, которых нет в OCR, переводить по картинке. Никогда не «сглаживать» разрыв в тексте догадкой —
лучше `[illegible]`.

**Карта пропусков OCR (сделано скриптом, 2026-10-17): `ocr/B-gaps/pNNNN.txt`.** Скрипт `tools/ocr_gaps.py` сравнил
каждую страницу-картинку с рамками слов tesseract и нашёл места, где на картинке есть текст, а в OCR его нет. Для
такой страницы файл говорит, сколько строк потеряно и **между какими строками OCR** (первые слова строки до и после
пропуска). Сводка по всем страницам — `ocr/B-gaps/INDEX.tsv`. Нет файла — пропусков на странице не найдено (но
картинку всё равно смотреть: скрипт не ловит перепутанные буквы и цифры). Пропуски в колонтитуле помечены
«вероятно, колонтитул» — их можно не переводить.

## 5. Системная инструкция переводчику (вставить в Codex / в проект ChatGPT)
> Ты переводишь с бенгальского на английский книгу «Шри Гаура-паршада о Гаудия-ачарьяганера чаритавали»
> (жизнеописания спутников Шри Чайтаньи и гаудия-ачарьев). Перевод служебный: по нему потом составляют точный
> реестр фактов. Поэтому важнее всего ПОЛНОТА и ТОЧНОСТЬ, а не красота.
>
> ЖЁСТКИЕ ПРАВИЛА:
> 1. Переводи страницу за страницей, полностью, от первой до последней строки. Ничего не пропускай, не сокращай,
>    не пересказывай, не объединяй абзацы разных страниц.
> 2. Ничего не добавляй от себя: ни пояснений, ни «общеизвестных» фактов, ни выводов. Чего нет на странице — нет в
>    переводе. Свои пометки — только в квадратных скобках и только служебные (§ 6).
> 3. Каждое имя, родство, место, дату, число, название книги, Божества, ссылку на источник переноси ТОЧНО. Числа
>    бенгальскими цифрами — арабскими. Не исправляй и не «уточняй» данные автора, даже если считаешь их ошибкой
>    (можно отметить [sic?]).
> 4. ИСТОЧНИКИ: OCR `ocr/B/pNNNN.txt` + картинка страницы. Работай ПО ОДНОЙ СТРАНИЦЕ. Картинка нужна
>    в разной степени (2026-10-18, чтобы не терять скорость):
>    — есть файл `ocr/B-gaps/pNNNN.txt` с местом «целая строка» / «~N строк» → картинку 300 dpi (`pdftoppm -r 300`),
>      каждое такое место читать по ней (п. 10);
>    — нет такого файла (или в нём только «часть строки» / «колонтитул») → переводить по OCR, картинку 150 dpi
>      (`-r 150`) открыть и бегло сверить ход строк; 300 dpi — только для неразборчивого имени, числа, стиха;
>    — всегда по картинке: числа, имена, ссылки, стихи и песни, где OCR выглядит странно.
>    Не уверен в чтении слова — дай транслитерацию и пометь [?]; не можешь прочесть — [illegible]. Никогда не
>    угадывай имя или число молча: [?] всегда лучше догадки.
> 5. Перед каждой страницей ставь маркер печатной страницы: `[B 892]` (номер, напечатанный на странице); если
>    номера не видно — `[B pdf 916]`.
> 6. Стихи (санскрит, бенгали), которые цитирует автор: дай ссылку, как у автора (ЧЧ Ади 10.45, Бхаг. 1.2.6 и
>    т. п.), первые 3–5 слов оригинала латиницей и буквальный перевод стиха. **Исключение по просьбе пользователя:**
>    прямые цитаты из «Шри Чайтанья-чаритамриты» (CC) и «Шри Чайтанья-бхагаваты» (CB) не переводи — их перевод у
>    нас есть. Пиши только `[verse: CC Adi 5.205–207] jagai madhai haite… — …pApa haya` — точная ссылка, как у
>    автора, **первые и последние 3–5 слов** цитаты латиницей (по ним проверяется, верна ли ссылка автора; авторы
>    ошибаются в номерах). «Шримад-Бхагаватам» и все прочие стихи («Падьявали», ГГД, БР и др.) — переводить,
>    как сказано выше (кратко, буквально). Собственный бенгальский пересказ или пояснение цитаты у автора переводи всегда и полностью, с
>    пометкой (author's Bengali rendering), если это пересказ.
> 7. Не сжимай мысль автора: противопоставления («не то…, а это»), пояснения, оговорки, перечни и примеры
>    передавай полностью, даже если они кажутся повтором (пример потери: B 79 — о Вене).
> 8. Стиль: простой, ясный, буквальный английский; одно бенгальское предложение — одно английское (длинные можно
>    делить). Богословские термины не заменять западными аналогами (см. глоссарий).
> 9. Формат ответа — строго § 7. В конце каждой главы — список неясных мест.
> 10. ПРОПУСКИ OCR. Если для страницы есть `ocr/B-gaps/pNNNN.txt`, в каждом месте «целая строка» / «~N строк»
>    прочти пропавший текст ПО КАРТИНКЕ и переведи (места «часть строки» и «колонтитул» — обычно ложная тревога,
>    достаточно беглого взгляда); перед этим текстом поставь `[from image]`. Не можешь прочесть — `[from image:
>    illegible]`. Не заполняй пропуск по смыслу соседних строк (так в прежних главах появлялись выдуманные фразы:
>    «чувства игр Гауры» вместо «чувства Радхи», «сын Парамананды Сена» вместо «сын, Кави Карнапура»).
> 11. ЯКОРЬ АБЗАЦА. Каждый абзац перевода начинай с `{bn: …}` — первые 3–4 слова этого абзаца бенгальским
>    письмом, точно как на странице (по картинке). Каждый абзац оригинала — свой абзац перевода, ни одного не
>    объединяй и не пропускай. По якорям скрипт проверяет, что ни один абзац не потерян и не сжат.
> 12. СОКРАЩЕНИЯ, ИМЕНА, ССЫЛКИ — по § 8а и `charitavali-en/NAMES.md`. Особенно: অঃ / অন্ত্য = Antya (НЕ Adi!),
>    আঃ = Adi, মঃ = Madhya. Ссылку переноси со всеми числами и диапазонами («৫।১০৭-১০» = 5.107–110). Имя, которого
>    нет в NAMES.md и которое читается неуверенно, — транслитерация по картинке + [?].
> 13. КОРОТКАЯ САМОПРОВЕРКА СТРАНИЦЫ перед следующей: (а) числа и ссылки (চৈঃ চঃ …, с верной частью Ади/Мадхья/
>    Антья) перенесены и совпадают с OCR/картинкой; (б) места «целая строка» из `ocr/B-gaps` — с `[from image]`;
>    (в) нет фраз-обобщений вместо текста («the examples above support this», «and so on», «etc.» вместо перечня).
>    Число абзацев отдельно не пересчитывай — это сделают якоря `{bn:}` и скрипт (п. 14).
> 14. После главы запусти `python3 tools/check_translation.py charitavali-en/NNN-…md -o charitavali-en/checks/NNN.md`
>    и пройди КАЖДОЕ отмеченное место по картинке: исправь перевод или допиши в checks/NNN.md, почему всё верно
>    (например, «число 1107 — ошибка OCR, на картинке 5.107–110»). Глава сдаётся только с этим файлом.

## 6. Пометки (единые)
- `[?]` — сомнительное чтение или понимание (после слова; в списке в конце главы — варианты).
- `[illegible]` — не читается.
- `[sic?]` — у автора, вероятно, ошибка (дата, имя), но переведено как есть.
- `[verse: <ссылка>]` — начало цитаты стиха.
- `[footnote]` — подстрочное примечание книги (переводить полностью, на месте после абзаца, к которому оно
  относится).
- `[photo: подпись]` — подпись к фотографии/иллюстрации (переводить подпись; само фото не описывать).
- `[table]` — таблица/родословное древо: передать списком «отец → сын…» строго как на странице.
- `[from image]` — дальше идёт текст, которого нет в OCR и который прочитан по картинке (§ 5, п. 10).
- `{bn: প্রথম তিন চার শব্দ}` — якорь в начале каждого абзаца: его первые слова бенгальским письмом (§ 5, п. 11).

## 7. Формат файла главы
```
# 071 — গদাধর দাস — Gadadhara Dasa
Pages: B 892–896 (pdf 916–920)
Also named in this chapter: Nityananda, Raghava Pandita, Madhava Ghosh … (все лица, упомянутые в главе)

[B 892]
{bn: শ্রীগদাধর দাস প্রভু} <paragraph>

{bn: তিনি এঁড়িয়াদহে} <paragraph … [from image] text missing in OCR, read from the page image … paragraph>

[B 893]
…

---
Unclear readings:
1. [B 893] "Eṛiyādaha [?]" — could be Eṇḍiyādaha; image unclear.
Verses quoted: CC Adi 10.53 [B 894]; Bhag. 11.2.42 [B 895]
```

Список «Also named», «Verses quoted», «Dates mentioned» в конце/начале — обязателен: по нему Claude находит
упоминания лиц в чужих главах без чтения всей книги.

`INDEX.md` — таблица: `| NNN | бенгальское заглавие | Name (EN) | печ. стр. | pdf стр. | файл | статус |`.
Составить его **первым шагом** по оглавлению книги (это дёшево и сразу нужно проекту).

Цифры OCR ненадёжны: «1» и «|» часто стоят вместо данды «।» (১০1৮৭ = 10.87), «€» — вместо ৫. Числа — только по картинке.

**Имена и названия** — `charitavali-en/NAMES.md` (выгружено из базы проекта: лица, места, книги в принятой латинице
и известные ошибочные чтения). Имя из списка — писать как в списке.

## 8. Глоссарий и транслитерация (EN)
Общая система — как в наших EN-текстах (простая латиница без диакритики в тексте; IAST — только в «Unclear
readings» и для первых слов стихов):
- ব → **v** в санскритских именах и терминах (Vishnu, Vaishnava, Vrindavana, Vasudeva), **b** в бенгальских словах и
  топонимах по общепринятому написанию (Bardhaman, Burdwan не менять; Bagnapara, Baranagar). Сомнение — v + [?].
- শ, ষ → sh (Shachi, Shrivasa, Krishna); স → s; ক্ষ → ksh; জ → j; য → y в санскритских именах (Yadunandana, не
  «Jadunandana»; Yamuna), в бенгальских топонимах — по общепринятому написанию; ঋ → ri (Krishna); চ → ch; ছ → chh;
  ং/ঁ → n/m по общепринятому.
- Окончание санскритских имён — с -a: Gadadhara, Damodara, Raghunatha, Gopinatha, Navadvipa, Nilachala (но
  устоявшиеся бенгальские формы: Nimai, Nitai, Haridas → Haridasa).
- Почётные: শ্রী — Sri (перед именем), শ্রীল — Srila, শ্রীমৎ — Srimat, ঠাকুর — Thakura, গোস্বামী — Gosvami,
  প্রভু — Prabhu, আচার্য — Acharya, পণ্ডিত — Pandita, মহাশয় — Mahashaya, বাবাজী — Babaji.
- Принятые имена: Sri Chaitanya, Mahaprabhu, Gauranga, Gaurasundara, Nityananda, Advaita Acharya, Gadadhara
  Pandita, Shrivasa Pandita, Haridasa Thakura, Svarupa Damodara, Raya Ramananda, Rupa Gosvami, Sanatana Gosvami,
  Jiva Gosvami, Raghunatha Dasa Gosvami, Gopala Bhatta Gosvami, Krishnadasa Kaviraja, Vrindavana Dasa Thakura,
  Narottama Dasa Thakura, Shrinivasa Acharya, Shyamananda, Bhaktivinoda Thakura, Bhaktisiddhanta Sarasvati,
  Gaurakishora Dasa Babaji, Jagannatha Dasa Babaji.
- Места: Navadvipa, Mayapura, Shantipura, Kulia, Katwa (Katoa), Shrikhanda, Khardaha, Panihati, Jagannatha Puri
  (Nilachala), Vrindavana, Radha-kunda, Govardhana, Shrihatta (Sylhet).
- Книги: Chaitanya-charitamrita (CC), Chaitanya-bhagavata (CB), Bhakti-ratnakara (BR), Gaura-ganoddesha-dipika (GGD),
  Prema-vilasa (PV), Narottama-vilasa (NV), Advaita-prakasha, Bhagavatam (Bhag.), Gita; ссылки — как у автора.
- Термины — транслитерацией с кратким пояснением при первом появлении в главе, дальше без пояснения: prema (divine
  love), bhava, rasa, lila (pastimes), kirtana, sankirtana, diksha (initiation), sannyasa, mahaprasada, samadhi
  (tomb/memorial of a saint), bhajana, tilaka, mantra, Hari-nama, tirobhava (disappearance), avirbhava (appearance),
  shakti, tattva, Deity (виграха / шри-мурти — always "Deity", never "idol/statue/image").
- Даты: эра указывается всегда — Shaka, Bengali era (B.S., বঙ্গাব্দ), Gaurabda, Vikrama samvat, A.D.; месяцы —
  бенгальские названия латиницей (Phalguna, Chaitra, Vaishakha…), титхи — как есть (Krishna-trayodashi). Не
  пересчитывать эры самому.
- Богословские запреты (как во всём проекте): Господь не подвластен майе; Божество — Deity, не idol/statue;
  према гопи — divine love, не passion/lust; уход Господа и чистых преданных — disappearance / entered into the
  eternal pastimes, не death (если автор пишет «দেহত্যাগ» — "left the body", не "died"); «безумие» — divine madness.

## 9. Порядок работы
1. **Шаг 0 — INDEX.md** по оглавлению книги (печатные и PDF-страницы каждой главы) — одной задачей.
2. **Пилот — 3 главы**, которые Claude уже разбирал или скоро будет: Джаганнатха Мишра (B 710–715), Гададхара дас,
   Джива Госвами (самая большая, ~81 с.). Пользователь отдаёт их Claude на проверку (§ 10) — по замечаниям
   уточняется этот файл.
3. **Основной проход** — партиями по 3–5 глав (или 20–40 страниц). Каждая партия — отдельный сеанс/задание с
   чистым контекстом (длинный чат начинает пропускать и сочинять).
4. После каждой главы: файл главы, строка в INDEX.md (статус «done»), неясные места — и в `NOTES.md`; коммит.
5. Длинные главы (Джива Госвами, Нитьянанда, ачарьи XIX–XX вв.) — делить на части по 20–30 страниц
   (`NNN-<slug>-part1.md` …).

## 10. Проверка (что делает Claude и что — пользователь)
- **Пользователь после каждой партии (5 минут):** все страницы диапазона есть (маркеры `[B N]` подряд, без
  пропусков); в конце главы есть списки; поиск стоп-слов: `idol`, `statue`, `image of`, `died` (о Господе/спутниках),
  `lust`, `passion`.
- **Claude — выборочно** (пилот целиком, затем ~1 главу из 10 и все главы, где много [?]): сверка 2–3 страниц с
  картинкой оригинала — полнота, имена, числа, даты, стихи; найденные систематические ошибки — правило в этот файл.
- **Брак** (пропущенная страница или абзац, выдуманный факт, «исправленная» дата) — главу переводить заново.
- **Автоматически (без ИИ), до сдачи главы:** `python3 tools/check_translation.py charitavali-en/NNN-….md -o
  charitavali-en/checks/NNN.md` — сверка с OCR по страницам: пропуски OCR без `[from image]`, перепутанные части ЧЧ
  (Антья/Ади), числа OCR, которых нет в переводе, сжатые страницы и абзацы (по якорям `{bn:}`). Каждое отмеченное
  место переводчик проверяет по картинке (§ 5, п. 14). Claude прогоняет тот же скрипт при приёме главы.

## 11. Как Claude использует перевод (для `parshadas/`)
- Источник **B** в реестре фактов = этот перевод; ссылки — те же `[B 892]` (печатные страницы).
- Факты Claude берёт из перевода; бенгальский оригинал открывает только для мест с `[?]`, `[illegible]`,
  `[sic?]` и для выборочной сверки.
- Текст статей пишется своими словами по реестру (как в `parshadas/TASK.md`); формулировки перевода в статьи не
  переносятся.
